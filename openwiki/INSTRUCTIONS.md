A knowledge wiki for the Kissaten coffee bean discovery platform. This wiki covers three overlapping areas:

1. **Code & Architecture** — Concise quickstart, architecture overview, source map, key workflows, operations/runbook notes, testing guidance, and integration points. Inspect git history to understand reasoning behind code changes. Keep pages grounded in the repository structure and recent code changes. Prefer practical navigation for engineers over generic summaries.

2. **Coffee Domain Concepts** — Document the specialty coffee knowledge that underpins this database: coffee processing methods (washed, natural, honey, anaerobic), varieties (Bourbon, Gesha, Catuai, etc.), origin geography (countries, regions, elevations, the coffee belt), roast levels and profiles, cupping scores, tasting note taxonomy, price transparency fields (FOB, farm gate price), and decaffeination. Explain why the data model captures each field and how the domain concept maps to schema fields in BEAN_DATA_FORMAT.md and the Pydantic models. These pages help future contributors understand not just how the code works but why specific coffee attributes are modeled the way they are.

3. **Design & UX Concepts** — Document the product design decisions that make this coffee database useful: the guided discovery experience (explore by flavour, process, or varietal), faceted filtering system, the interactive origin map, bean detail page information architecture, roaster/origin exploration flows, and the analytics/insights dashboards. Explain how each design pattern helps users discover and compare coffee, and reference the frontend components and API endpoints that implement them.

When documenting, link between these three areas: a coffee domain concept should point to the schema fields and UI that implement it; a design pattern should reference the domain concepts it surfaces and the components that render it; a code page should reference the domain concepts it operates on. The goal is a wiki that helps both engineers and coffee-savvy contributors understand the system end to end.
